# 11 — Integração Contínua

Workflow: `.github/workflows/ci.yml`. Roda em `push` para `main` e em todo
`pull_request`. Execuções duplicadas no mesmo ref são canceladas
(`concurrency: cancel-in-progress`).

## Jobs

### `qualidade`

| Passo | Comando | O que pega |
|---|---|---|
| Instalar dependências | `pip install -r api/requirements.txt` + `pytest ruff` | Requirements quebrado ou não instalável |
| Erros de sintaxe e nomes indefinidos | `ruff check --select E9,F63,F7,F82 .` | `SyntaxError`, nome indefinido, `is` com literal, `assert` em tupla |
| Compilar todos os módulos | `python -m compileall -q api app frontend tests` | Arquivo que nem compila |
| Testes | `pytest tests/ -q` | Integridade do menu (abaixo) |

`app/requirements.txt` **não** é instalado: torch + transformers + faiss passam de 2 GB
e nenhum teste importa o pipeline RAG. Se um dia houver teste que precise dele, vale um
job separado com cache do modelo de embeddings.

O `ruff` roda com o subconjunto de erros reais, não de estilo. O código nunca passou por
linter; ligar as regras de estilo agora encheria o CI de ruído sem pegar nenhum bug.
Estilo pode ser adotado depois, arquivo por arquivo.

### `migracoes`

Dois passos, ambos com `working-directory: api` e `DATABASE_URL: sqlite:///ci.db`:

| Passo | Comando | O que pega |
|---|---|---|
| Cadeia de revisões resolve | `alembic heads` | `down_revision` órfão, head duplicado após merge malfeito |
| Upgrade completo | `alembic upgrade head` | DDL quebrado em qualquer revisão da cadeia |

`alembic heads` resolve o grafo **sem conectar no banco** — o `env.py` nem chega a rodar.
O `alembic upgrade head` roda de verdade, contra um sqlite descartável.

Sqlite não é Postgres: diferenças de DDL (tipos, `ALTER` com constraint) passam aqui e
falham em produção. Ainda assim pega a classe de erro mais comum, e custa zero — sem
`services:`, sem container. Um job com Postgres real é o próximo degrau.

> Este job nasceu vermelho, apontando o problema 1 de
> [doc 10](10-problemas-conhecidos.md): o merge `f36d189f393f` referenciava
> `a8f3b1c2d4e5`, apagada por engano do repositório. Já corrigido — as revisões foram
> restauradas e o job está verde. Fica no lugar para impedir a reincidência, que é
> exatamente como o bug entrou: arquivo de migração perdido num refactor.

## Testes

### `tests/test_chat_service.py`

Máquina de estados completa: onboarding, validação de nome, comandos, navegação de menu,
texto livre, modo manutenção, persistência. Roda contra **sqlite em memória com os models
reais** — nada de mock de sessão. O `NLPService` entra como dublê, porque o que se testa
aqui é o roteamento da conversa, não a qualidade da resposta do RAG.

Isso só passou a ser possível quando `chat_service` deixou de importar `NLPService` em
tempo de execução (`TYPE_CHECKING`). Antes, importar o módulo baixava o modelo de
embeddings — era o bloqueio listado como próximo passo nesta mesma página.

### `tests/test_migracao_id_wpp.py`

A migração `d2f3a4b5c6d7` reescreve uma coluna `UNIQUE` em linhas de produção. O caso
perigoso é a colisão: sem a guarda, o `UPDATE` estoura e a migração morre no meio, com
parte das linhas já alteradas. O teste carrega o arquivo da migração por caminho e chama
`normalizar_usuarios` direto, sem precisar de contexto do Alembic.

### `tests/test_intencao.py`

Detecção de saudação, que substituiu uma chamada de LLM por mensagem. O erro que importa é
o falso positivo: classificar `"Oi, onde fica o CEMERF?"` como saudação faria o bot
responder "Olá! Como posso ajudar?" e engolir a pergunta do cidadão.

### `tests/test_security.py`

Autenticação das rotas de entrada. O foco é o comportamento **em falha**: variável de
ambiente ausente, header ausente, token errado, corpo adulterado, URL diferente. Todos
têm que negar — um `return True` acidental em qualquer desses ramos reabre a rota para o
mundo inteiro, sem sintoma visível.

`api/security.py` não importa `app/` nem os services justamente para caber no CI: se
importasse, o teste arrastaria LangChain e o download do modelo de embeddings.

### `tests/test_menu_texts.py`

`menu_texts.json` é **dado**, não código: um `next_state` com typo não quebra o
processo, só derruba o cidadão num beco sem saída dentro do WhatsApp. Esse é o modo de
falha mais provável do repositório, e o mais barato de testar.

104 casos, todos parametrizados por estado:

| Teste | Garante |
|---|---|
| `test_menu_json_e_valido` | JSON parseia e tem pelo menos um estado |
| `test_menu_principal_existe` | `WAITING_MAIN_MENU` existe — é o destino do fallback do `ChatService` |
| `test_estado_tem_texto_e_opcoes` | Todo estado tem `text` e `options` não vazio |
| `test_opcao_tem_exatamente_um_comportamento` | Cada opção tem `next_state` **ou** `query`, nunca ambos nem nenhum |
| `test_next_state_aponta_para_estado_existente` | Nenhum `next_state` órfão |
| `test_todo_estado_e_alcancavel` | Nenhum estado inacessível a partir do menu principal |
| `test_submenu_permite_voltar` | Todo submenu tem a opção `0` |
| `test_image_key_tem_fallback_declarado` | Todo `image_key` tem entrada em `FLOW_IMAGE_URLS` (último nível da cascata — ver [doc 09](09-configuracao-e-midias.md)) |

Constantes que o teste precisa conhecer sobre o código:

```python
NON_STATE_KEYS   = {"FLOW_IMAGE_URLS"}      # chave do JSON que não é estado
CODE_ONLY_STATES = {"NEW", "WAITING_NAME"}  # estados criados pelo ChatService
```

Se o `ChatService` ganhar novos estados fora do JSON, some-os a `CODE_ONLY_STATES`.

## Rodar localmente

```powershell
pip install -r api/requirements.txt
pip install pytest ruff
pytest tests/ -q
ruff check --select E9,F63,F7,F82 .
python -m compileall -q api app frontend tests
```

```powershell
cd api
$env:DATABASE_URL = "sqlite:///ci.db"
alembic heads
```

## Próximos passos naturais

Em ordem de custo/benefício, conforme os problemas de [doc 10](10-problemas-conhecidos.md)
forem sendo resolvidos:

1. **Job de smoke com Postgres** (`services: postgres`) rodando `alembic upgrade head` no
   banco real — cobre o que o sqlite não cobre.
2. **Verificação de segredo commitado** (gitleaks ou similar) — o problema 3 já mostrou
   que uma chave passa despercebida numa revisão de PR.
3. **Avaliação do RAG** — um conjunto de perguntas com resposta esperada, rodado sob
   demanda e não a cada push, por causa do modelo e da cota da Groq. É o que falta para a
   troca do modelo de embeddings deixar de ser um palpite informado.
